# Chronos Vault — 대용량 CSV 시계열 뷰어 (웹)

[binjr](https://binjr.eu)의 핵심 기능을 옮긴, Obsidian 테마의 시계열 뷰어입니다.
차트 하나하나가 **위젯**이고, 워크시트(**탭**) 화면을 Obsidian처럼 **분할 타일**로 나눠 채웁니다.
설치 없이 브라우저(Chrome·Edge 권장)에서 돌아갑니다. 데이터 처리는 Rust 엔진을
WebAssembly로 컴파일해 별도 작업 스레드(Web Worker)에서 하고, 화면에는 그릴 점만 보내므로
수백 MB~GB 단위 CSV도 다룹니다.

## 사용법

| 작업 | 방법 |
|---|---|
| CSV 열기 | 창에 끌어다 놓기, 리본의 폴더 아이콘, `Ctrl+Shift+O` |
| 열 고르기 (가져오기 창) | 정규식 검색 (`temp\|press`, `^tag_00[1-3]`), **모두 선택 / 모두 해제 / 숫자 열만** — 검색된 열에만 적용 |
| 열 찾기 (탐색기) | 정규식 검색, 소스를 끌면 **검색된 열만** 차트에 추가, 소스 우클릭 → 검색된 열 선택 / 새 차트 |
| 워크스페이스 열기 | `.chronos`를 창에 끌어다 놓기, `Ctrl+O`, 탐색기의 최근 파일 |
| 저장 / 다른 이름 | `Ctrl+S` / `Ctrl+Shift+S` |
| 차트 만들기 | 탐색기의 열을 차트 가운데(추가) 또는 가장자리(그쪽에 새 타일)로 끌기, 더블클릭 |
| 타일 배치 | 헤더를 다른 타일 가장자리로 끌기 = 그쪽에 붙이기, 가운데 = 자리 바꾸기, 탭으로 = 다른 워크시트로. 경계선 끌기 = 크기, 더블클릭 = 반반. 맨 위 단계의 가로 경계선과 워크시트 아래 손잡이는 위젯을 밀어내며 **워크시트를 화면보다 길게** 늘립니다 (스크롤, 손잡이 더블클릭 = 화면 높이로) |
| 정렬 (PowerPoint식) | 툴바 **정렬** 메뉴: 모든 위젯 높이/너비 균등 분배, 선택 위젯의 세로줄 높이·가로줄 너비 맞추기, 위·아래·왼쪽·오른쪽 위젯과 자리 바꾸기 (`Alt+Shift+방향키`) |
| 주석 | `N` 또는 툴바의 주석 버튼 → 그래프 **클릭 = 그 시점**, **드래그 = 그 구간**. 메모·색과 함께 그 시점의 값(구간이면 최소·최대·평균)과 당시 화면(시간 범위, Y축 확대, 보이던 시리즈)이 저장됩니다. 오른쪽 사이드바 **주석** 탭에서 검색·편집·삭제하고, 항목을 클릭하면 주석을 달던 화면으로 돌아갑니다. 그래프의 핀·띠를 클릭하면 메모를 봅니다 |
| 차트 플러그인 | 리본의 퍼즐 아이콘 / 워크시트 툴바 **+** → 산점도·회귀(R²), 시간대 히트맵, 밀도 히트맵, 히스토그램, 상관행렬. 파라미터는 속성 패널에서 고르거나 탐색기의 열을 차트 가운데로 끌어 놓기 |
| LLM으로 플러그인 만들기 | 플러그인 관리 → **플러그인 명세서 복사** → Claude·ChatGPT에 붙여넣고 원하는 그래프 설명 → 받은 답(코드 블록째)을 붙여넣고 **불러오기** |
| 시리즈 하나만 보기 | 범례 행 `Ctrl`+클릭 (다시 `Ctrl`+클릭 = 모두 보기) |
| 시리즈 옮기기 | 범례 행을 다른 위젯으로 끌기 (`Ctrl` = 복사) |
| 줌 / 이동 | 드래그 = 구간 확대, `Ctrl`+휠 = 시간축 확대/축소, `Shift`+휠 = 좌우 이동 (그냥 휠은 워크시트 스크롤), `Shift`+드래그·가운데 버튼 = 이동, 더블클릭 = 초기화, `←/→`, `+/-`, `A` |
| 문제 보고 | 명령 팔레트(`Ctrl+P`) → **진단 로그 저장** |

차트 하나에는 시리즈를 64개까지 넣습니다 (그 이상은 읽을 수 없고 화면 갱신마다 수십 MB가 오갑니다).

### 워크스페이스 파일 (.chronos)

- 레이아웃과 **전처리 결과(파싱된 값 + 블록 인덱스)를 크기와 관계없이 항상 같은 파일에** 저장합니다.
  다시 열면 CSV 없이도 바로 보입니다.
- 브라우저에는 파일 경로가 없어서, Chrome·Edge에서는 열었던 워크스페이스와 CSV의 **파일 핸들**을 기억합니다.
  - 다음 방문 때 마지막 워크스페이스는 "다시 열기" 버튼 한 번으로 열립니다 (브라우저 권한).
  - 원본 CSV 접근을 허용하면(버튼 한 번) 바뀐 CSV를 같은 설정으로 자동 재처리합니다.
- 저장하기 전 작업은 브라우저 저장소(OPFS)의 **Untitled**에 자동 보관되고, 다음 방문 때 그대로 복원됩니다.
- 헤더가 파일 끝에 있어, 브라우저 저장소(Untitled)에서는 레이아웃만 바뀐 저장이 수 KB만 덧붙입니다 (약 0.1초).
  사용자가 고른 파일은 브라우저가 항상 사본을 만들어 바꿔치기하므로, 저장할 때마다 전체를 다시 씁니다
  (테스트 VM에서 341 MB 약 3초).
- Firefox·Safari처럼 파일 핸들이 없는 브라우저에서는 열기는 파일 선택, 저장은 다운로드로 동작합니다.

### 차트 플러그인

- 플러그인은 `export default { id, name, version, params, render(ctx) }` 형태의 JavaScript 파일 하나입니다.
  기본 제공 차트도 같은 형식(`src/plugins/builtin/`)이고, 명세서는 `src/plugins/spec.ts` 에 있습니다.
- 플러그인은 `sandbox="allow-scripts"` iframe(불투명 출처) + 네트워크를 막은 CSP 안에서 실행되어
  인터넷·파일·브라우저 저장소·앱 화면에 접근할 수 없습니다. 데이터는 `ctx.data` 로 엔진에 집계를 요청해
  받습니다 (시각 맞춤 행, 회귀, 히스토그램, 2D 히스토그램, 달력 집계, 다운샘플, 원본 샘플).
- d3 v7이 전역으로 제공됩니다. 불러온 플러그인은 브라우저(내 플러그인)에, 위젯에 쓴 플러그인은 워크스페이스
  파일에도 저장됩니다.

### 한도

- 엔진 메모리는 탭당 약 **4 GB**(32-bit WebAssembly)입니다. 가져오기 창이 예상 메모리를 보여 주고,
  큰 파일은 자동으로 32-bit 값(메모리 절반)을 고릅니다.

## 구조

```
engine/          Rust 데이터 엔진 (chronos-engine)
  src/csv.rs       미리보기·감지, 병렬 파서, 조각 단위 가져오기(StreamImport)
  src/time.rs      타임스탬프 파싱 (ISO / D.M.Y / M/D/Y / epoch)
  src/series.rs    값 저장 (f64/f32), 64행 블록 인덱스, M4 다운샘플, 구간 통계
  src/chronos.rs   .chronos v3 형식 (끝에 헤더, 추가 저장 계획)
  src/lib.rs       Engine::call — 공통 명령
engine-wasm/     브라우저용 WebAssembly 모듈 (bindgen 없이 alloc/call/out 내보내기)
src/             UI (TypeScript, uPlot, gridstack)
  engineWorker.ts  Web Worker: wasm 엔진 + 모든 파일 입출력 (조각 읽기, OPFS, 파일 핸들)
  engine.ts        엔진 클라이언트 (메시지)
  project.ts       워크스페이스 파일, 자동 보관, 최근 파일, 원본 CSV 재처리
  dialogs.ts       파일 선택·저장, 핸들 보관(IndexedDB), 끌어다 놓기
  ui/              셸, 위젯, 탐색기, 가져오기 창, 속성, 탭, 드래그 앤 드롭
src-tauri/, engine-bridge/   이전 데스크톱 앱 (더 이상 배포하지 않음)
```

## 개발

필요: Node 20+, Rust stable + `rustup target add wasm32-unknown-unknown`.

```bash
npm install
npm run dev            # wasm 빌드 후 http://localhost:5173
npm run build          # dist/ (정적 파일 — GitHub Pages 등 어디든)
cargo test -p chronos-engine --release
```

`.cargo/config.toml`이 wasm 빌드에 SIMD·bulk-memory를 켭니다 (CSV 파싱 약 6배 빠름).
